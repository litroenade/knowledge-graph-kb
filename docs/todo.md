# 前端图谱工作台 TODO

本文档记录下一批前端图谱能力的规划。目标不是继续堆功能按钮，而是把当前 Pixi 图谱升级成可长期整理、可控筛选、可读性更强的知识图谱工作台。

## 当前状态

当前新版 `frontend` 已具备：

- Pixi 图谱渲染。
- d3-force 物理布局。
- 拖拽画布、滚轮缩放。
- 点击节点打开检查器。
- 点击边打开检查器。
- 节点 hover 时由运行时处理临时上下文标签。
- 聚焦节点时高亮一度、二度邻居。
- 空白点击重置选择。
- 全局图 / 局部图切换。
- 语义图 / 证据图 / 结构图切换。
- 密度、标签显示、物理开关、连接距离、斥力控制。
- 来源范围筛选。
- 普通节点搜索，当前主要是字符串包含匹配。
- 导入中心。
- 问答 / 结构化检索面板。
- 模型配置 / 索引状态面板。
- 新增、重命名、删除节点。
- 新增、删除手工关系。
- 删除图谱关系。
- 来源详情、段落预览、表格预览。

当前暂不做：

- 画像管理。

当前后端尚未开放 HTTP API，前端暂不伪造调用：

- 回收站。
- 记忆强化 / 保护 / 冷冻。
- 向量重建任务接口。

## 下一批目标

下一批聚焦五件事：

1. 布局持久化。
2. 节点拖拽固定。
3. 关系 / 标签高级筛选。
4. 图谱分组配色。
5. 拼音 / 模糊搜索。

这批能力的核心价值是：

- 可记忆：用户整理好的图谱位置可以保留下来。
- 可控：用户可以固定关键节点，不再被物理模拟推走。
- 可筛：大图可以按节点类型、关系类型、证据强度快速收窄。
- 可读：不同来源、类型、社群可以被颜色区分。
- 可找：中文、ID 片段、近似输入都能更快定位节点。

## 1. 布局持久化

### 现在如何

当前节点位置主要由 runtime 和物理模拟计算。重新加载图谱、切换视图或刷新页面后，用户整理过的布局不会稳定保留。

### 规划

在 `GraphRuntime` 增加布局快照能力：

- 暴露 `get_layout_snapshot()`。
- 暴露 `apply_layout_snapshot(snapshot)`。
- 快照记录每个节点的：
  - `node_id`
  - `x`
  - `y`
  - `fixed`
  - `updated_at`

第一版使用 `localStorage` 持久化：

- key 按图谱视图和范围组织。
- 推荐 key 结构：`amemorix:graph-layout:${view}:${scope_hash}`。
- `scope_hash` 基于当前来源范围、视图、密度等生成稳定值。

UI 增加：

- 保存布局。
- 自动保存布局。
- 恢复布局。
- 重置当前布局。

后续如果后端开放用户配置或 layout API，再把 localStorage 迁移到服务端。

### 预期效果

用户把图谱拖成自己习惯的形状后：

- 刷新页面仍能恢复布局。
- 切换面板不会丢失布局。
- 重新进入同一来源范围和视图时，核心节点仍在原位置。

### 验收标准

- 拖动节点后点击“保存布局”，刷新页面后节点位置保持。
- 点击“重置布局”后清除当前范围的持久化布局。
- localStorage 数据结构可读，且不会污染其他视图或来源范围。
- TypeScript 和测试通过。

## 2. 节点拖拽固定

### 现在如何

当前图谱有物理模拟和交互能力，但没有明确的“固定节点”产品状态。用户整理关键节点后，节点仍可能被后续物理模拟影响。

### 规划

在 runtime 内维护固定节点集合：

- 拖拽节点后默认标记为 fixed。
- fixed 节点不再被 d3-force 推动。
- 未固定节点继续参与物理模拟。
- 固定状态进入布局快照。

检查器或图谱控制区增加：

- 固定当前节点。
- 取消固定当前节点。
- 固定当前邻域。
- 释放全部固定。

### 预期效果

用户可以像使用 Obsidian 图谱一样，把核心节点钉在画布上：

- 核心概念稳定在用户指定位置。
- 周边节点继续自动排布。
- 重排布局不会破坏用户固定的核心骨架。

### 验收标准

- 拖拽一个节点后，该节点不会被物理模拟继续推走。
- 取消固定后，该节点重新参与模拟。
- 固定邻域后，一度邻居位置稳定。
- 保存布局后，固定状态可恢复。

## 3. 关系 / 标签高级筛选

### 现在如何

当前筛选能力主要包括：

- 来源范围。
- 图谱视图。
- 密度。
- 搜索。
- 全局 / 局部。

但还不能独立控制：

- 节点类型。
- 节点标签。
- 关系类型。
- 关系标签。
- 是否只看手工关系。
- 是否只看证据关系。
- 最小证据数量。
- 最小关系权重。

### 规划

从当前 graph 数据中提取筛选候选项：

- `node.type`
- `node.kind_label`
- `node.family`
- `edge.type`
- `edge.relation_kind_label`
- `edge.family`
- `node.evidence_count`
- `edge.weight`

新增图谱筛选状态：

- `enabled_node_types`
- `enabled_node_labels`
- `enabled_edge_types`
- `enabled_relation_labels`
- `min_evidence_count`
- `min_edge_weight`
- `manual_only`
- `evidence_only`

实现位置：

- 筛选计算放在 `graphModel.ts`。
- React 组件只负责展示控件和更新 state。
- 对筛选模型补单元测试。

### 预期效果

用户可以快速收窄大图，例如：

- 只看实体节点。
- 只看手工关系。
- 只看证据关系。
- 只看高权重关系。
- 只看某些关系谓词。
- 只看有足够证据支撑的节点。

### 验收标准

- 开关节点类型后，节点数量和边数量正确变化。
- 开关关系类型后，不相关边消失，孤立节点按规则处理。
- 最小权重筛选能稳定过滤低权重边。
- 筛选逻辑有模型层测试，删除核心筛选代码时测试会失败。

## 4. 图谱分组配色

### 现在如何

当前颜色主要按 `node.type` 和 `edge.type` 固定映射。它能区分基础类型，但不能表达来源簇、语义簇、结构簇或社群。

### 规划

新增配色模式：

- 按节点类型。
- 按来源。
- 按 family：`semantic` / `evidence` / `structure`。
- 按前端社群分组。

社群分组第一版可以采用轻量算法：

- 基于当前可见边构建无向连通分量。
- 每个连通分量分配一种颜色。
- 对超大连通分量后续再考虑 Louvain / label propagation。

UI 增加：

- 配色依据选择。
- 图例 legend。
- 保留默认低干扰配色。

### 预期效果

用户看大图时可以直接分辨：

- 哪些节点来自同一来源。
- 哪些节点属于同一结构区域。
- 哪些节点形成同一关系社群。
- 当前图谱中语义、证据、结构三类内容的分布。

### 验收标准

- 切换配色模式后，节点和图例同步变化。
- 同一来源的节点颜色一致。
- 同一连通分量的节点颜色一致。
- 颜色不影响选中、高亮、hover 的可读性。

## 5. 拼音 / 模糊搜索

### 现在如何

当前搜索主要是：

- `toLowerCase()`
- `includes()`
- 多字段拼接搜索

这对中文、拼音、错字、缩写不够友好。

### 规划

第一版先做无依赖模糊搜索：

- 多字段归一化：
  - label
  - display_label
  - id
  - kind_label
  - source_name
- 连续子串匹配。
- 字符序列匹配。
- 简单编辑距离或评分排序。
- 返回命中原因。

搜索结果展示：

- 名称命中。
- 类型命中。
- 来源命中。
- ID 命中。

拼音能力分两步：

1. 如果后端或数据 metadata 已有 alias / pinyin 字段，优先使用已有字段。
2. 如果没有，再评估引入轻量拼音库，避免无必要地增加包体积。

### 预期效果

用户可以通过这些输入找到节点：

- 中文全名。
- 中文局部片段。
- ID 片段。
- 来源名称片段。
- 类型名称。
- 简单缩写或非连续字符。

### 验收标准

- 搜索结果按匹配质量排序。
- 精确名称命中优先于模糊命中。
- ID 命中可以稳定定位节点。
- 搜索逻辑有测试覆盖。

## 建议实施顺序

建议按以下顺序推进：

1. 布局持久化 + 节点拖拽固定。
2. 关系 / 标签高级筛选。
3. 图谱分组配色 + 图例。
4. 拼音 / 模糊搜索。

原因：

- 布局持久化和节点固定会触碰 `GraphRuntime` 的核心交互状态，应先稳定。
- 高级筛选会改变 `project_graph` 的投影结果，是配色和搜索的基础。
- 分组配色依赖稳定的可见节点/边集合。
- 模糊搜索最后做，可以复用筛选后的节点索引，并避免搜索和筛选状态互相打架。
