## 1. 布局持久化

### 现在如何

当前节点位置主要由 runtime 和物理模拟计算。重新加载图谱、切换视图或刷新页面后，用户整理过的布局不会稳定保留。

### 规划

在 `GraphRuntime` 增加布局快照能力：

- 暴露 `get_layout_snapshot()`。
- 暴露 `apply_layout_snapshot(snapshot)`。
- 快照记录每个节点的：
  - `node_id`
  - `x`
  - `y`
  - `fixed`
  - `updated_at`

第一版使用 `localStorage` 持久化：

- key 按图谱视图和范围组织。
- 推荐 key 结构：`amemorix:graph-layout:${view}:${scope_hash}`。
- `scope_hash` 基于当前来源范围、视图、密度等生成稳定值。

UI 增加：

- 保存布局。
- 自动保存布局。
- 恢复布局。
- 重置当前布局。

后续如果后端开放用户配置或 layout API，再把 localStorage 迁移到服务端。

### 预期效果

用户把图谱拖成自己习惯的形状后：

- 刷新页面仍能恢复布局。
- 切换面板不会丢失布局。
- 重新进入同一来源范围和视图时，核心节点仍在原位置。

### 验收标准

- 拖动节点后点击“保存布局”，刷新页面后节点位置保持。
- 点击“重置布局”后清除当前范围的持久化布局。
- localStorage 数据结构可读，且不会污染其他视图或来源范围。
- TypeScript 和测试通过。

## 2. 节点拖拽固定

### 现在如何

当前图谱有物理模拟和交互能力，但没有明确的“固定节点”产品状态。用户整理关键节点后，节点仍可能被后续物理模拟影响。

### 规划

在 runtime 内维护固定节点集合：

- 拖拽节点后默认标记为 fixed。
- fixed 节点不再被 d3-force 推动。
- 未固定节点继续参与物理模拟。
- 固定状态进入布局快照。

检查器或图谱控制区增加：

- 固定当前节点。
- 取消固定当前节点。
- 固定当前邻域。
- 释放全部固定。

### 预期效果

用户可以像使用 Obsidian 图谱一样，把核心节点钉在画布上：

- 核心概念稳定在用户指定位置。
- 周边节点继续自动排布。
- 重排布局不会破坏用户固定的核心骨架。

### 验收标准

- 拖拽一个节点后，该节点不会被物理模拟继续推走。
- 取消固定后，该节点重新参与模拟。
- 固定邻域后，一度邻居位置稳定。
- 保存布局后，固定状态可恢复。

## 4. 图谱分组配色

### 现在如何

当前颜色主要按 `node.type` 和 `edge.type` 固定映射。它能区分基础类型，但不能表达来源簇、语义簇、结构簇或社群。

### 规划

新增配色模式：

- 按节点类型。
- 按来源。
- 按 family：`semantic` / `evidence` / `structure`。
- 按前端社群分组。

社群分组第一版可以采用轻量算法：

- 基于当前可见边构建无向连通分量。
- 每个连通分量分配一种颜色。
- 对超大连通分量后续再考虑 Louvain / label propagation。

UI 增加：

- 配色依据选择。
- 图例 legend。
- 保留默认低干扰配色。

### 预期效果

用户看大图时可以直接分辨：

- 哪些节点来自同一来源。
- 哪些节点属于同一结构区域。
- 哪些节点形成同一关系社群。
- 当前图谱中语义、证据、结构三类内容的分布。

### 验收标准

- 切换配色模式后，节点和图例同步变化。
- 同一来源的节点颜色一致。
- 同一连通分量的节点颜色一致。
- 颜色不影响选中、高亮、hover 的可读性。

## 建议实施顺序

建议按以下顺序推进：

1. 布局持久化 + 节点拖拽固定。
2. 关系 / 标签高级筛选。
3. 图谱分组配色 + 图例。
4. 拼音 / 模糊搜索。

原因：

- 布局持久化和节点固定会触碰 `GraphRuntime` 的核心交互状态，应先稳定。
- 高级筛选会改变 `project_graph` 的投影结果，是配色和搜索的基础。
- 分组配色依赖稳定的可见节点/边集合。
- 模糊搜索最后做，可以复用筛选后的节点索引，并避免搜索和筛选状态互相打架。

## 物理效果后续注意事项

本节记录第一版物理交互完成后仍需要跟踪的问题。这些问题有些不是纯物理问题，但会直接影响用户对图谱物理效果的判断。

### 1. API 错误会伪装成物理问题

现象：

- 浏览器控制台出现 `/api/kb/graph` 返回 `400 Bad Request`。
- 点击某些边时 `/api/kb/graph/edges/{edge_id}` 返回 `404 Not Found`。

影响：

- 图谱数据加载不完整时，用户会误以为节点布局或物理模拟异常。
- 边详情 404 会造成检查器报错，干扰点击边后的体验。

规划：

- `/api/kb/graph` 400 需要单独排查请求体和后端 schema 是否一致。
- 边详情 404 时，前端应降级为“该边为视图派生关系，暂无详情”，不要直接显示全局红色错误。
- 对结构边、派生边、证据边区分详情获取策略。

当前修复：
- `evidence` 视图没有选中节点或关系时，前端返回本地空图和提示，不再发送空锚点请求。
- `graph_edge_not_found` 只在检查器内展示“派生边或详情不存在”的提示，图上选边仍保留。
- API 错误文案集中在 `frontend/src/shared/api/errorMessages.ts`，避免各面板直接泄露底层异常文本。

### 2. 节点拖拽与画布拖拽事件竞争

现状：

- 节点拖拽开始时会暂停 `viewport.drag()`。
- 节点拖拽结束后会恢复 `viewport.drag()`。

仍需观察：

- 快速拖动节点时是否误触画布平移。
- 拖动过程中浏览器失焦或 pointer cancel 是否会残留拖拽状态。
- 拖一次节点后，画布拖拽是否始终能恢复。

后续加固：

- 已增加 `pointercancel` 清理。
- 已增加窗口 blur 清理。
- 后续继续观察拖拽状态异常时 viewport drag 是否稳定恢复。

### 3. 自动保存不能绑定 force tick

原则：

- 可以在节点拖拽结束后保存。
- 可以在固定/释放节点后保存。
- 可以在恢复/重置布局后更新状态。
- 不应在每个 force tick 写入 `localStorage`。

原因：

- force tick 频率高，持续写 localStorage 会造成卡顿。
- 大图下频繁同步布局快照会明显影响交互。

验收：

- 自动保存只由用户交互或明确布局命令触发。
- 物理模拟自然运行不应持续写存储。

### 4. 物理参数变化需要节流

现状：

- 连接距离、斥力变化后会重建 force simulation。
- 这保证了滑块不是只改 UI，而是真的影响运行时。

风险：

- 用户连续拖动 slider 时，会高频重建 simulation。
- 大图下可能造成短暂卡顿。

后续优化：

- 对 slider 增加 debounce。
- 或拆分为“预览值”和“应用值”，用户松手后再重建 simulation。

### 5. 固定节点太多会让布局变僵

现象：

- 用户固定大量节点后，剩余节点可能被挤压。
- 重排布局也会因为固定点太多而失去弹性。

后续功能：

- 释放当前邻域。
- 释放非选中节点。
- 固定核心节点、释放叶子节点。
- 视觉上区分 fixed 节点，例如外圈、锁图标或不同描边。

### 6. hover 标签数量需要上限

现状：

- 全局标签关闭时，hover/选中上下文标签仍会临时显示。

风险：

- 大图中某些 hub 节点邻居很多，hover 时可能瞬间生成大量 Pixi Text。
- 二度邻居过多时会遮挡画面。

后续优化：

- 限制 hover 标签数量，例如最多 80 个。
- 按 degree、距离、是否一度邻居排序。
- 二度邻居只高亮点，不默认显示所有标签。

### 7. 大图自动冻结策略需要分级

当前策略：

- 中等规模图谱运行一段时间后自动冻结。
- 大图由 runtime profile 禁用物理。

后续策略：

- 小图：持续物理，用户手动暂停。
- 中图：短时间运行，自动冻结。
- 大图：默认静态，只允许用户手动短时运行。
- 超大图：只做局部布局，不跑全图 simulation。

### 8. 布局 key 是否包含 density 需要产品确认

当前策略：

- 布局 key 包含 `view`、`scope`、`density`。

优点：

- 不同密度下节点集合可能不同，分开存储更安全。

缺点：

- 用户调整密度后，可能无法复用之前整理好的布局。

可选调整：

- 从 key 中移除 `density`。
- 恢复布局时只应用当前图谱中存在的节点。
- 对缺失节点忽略，对新增节点继续用螺旋初始位置。
